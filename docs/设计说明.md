# 萌萌表情包 — 设计说明

> PRD 全文在工作区 `docs/astrbot_plugin_moe_meme_PRD.md`（含 API 实测记录），本页只留架构要点与后续 TODO。

## 模块

- `main.py` — 全部 AstrBot 胶水：指令、llm_tool、消息监听、配置读写、会话状态。**不要加 `from __future__ import annotations`**（GreedyStr 哨兵按对象同一性识别，字符串化注解会让无参调用失效）。
- `wuwa_source.py` — 数据源。`StickerSource` 抽象暂未强行分层（只有 wuwa 一个源），加第二个源时再抽协议：`random_sticker(character?) -> Sticker` + `characters()`。
- `sticker_gate.py` — 防打扰闸门，纯函数无依赖，`tests/test_gate.py` 可独立跑。

## 关键设计决定

1. **图片链不缓存**：站方随机接口返回的 `url` 是带票券的临时链（约 16 分钟有效，307 跳 media.wuwa.games），一律现拉现发。缓存只做角色列表（archive-index 聚合，24h TTL）。
2. **主动发送必须显式逐会话 opt-in**（`proactive_sessions`），刻意不随白名单「空=全放行」——空配置不能在所有群乱发。
3. **两类主动发送（LLM 工具 / 关键词）共享同一份会话闸门状态**：对用户来说「bot 又刷表情」不分来源，冷却与每日限额合并计数；`/表情包 列表` 与指令去重也走同一份 `recent` 表。
4. **发送成功才记账**（冷却/限额/去重），发送失败不消耗额度。
5. **热重载**：`__init__` 按依赖序 reload `sticker_gate` / `wuwa_source` 并重新绑定全局名（box/anima 同款做法）；新增顶层模块必须同步 `__init__` 重载列表与 `build_zip.ps1` 的 `$includeList`（后者有构建期守卫，漏了会打包失败而不是静默缺件）。
6. **配置的 `type: "dict"`**（aliases / triggers）是 AstrBot 的自由键值表类型，`check_config_integrity` 会保留用户自加的键；与固定子字段的 `type: "object"`（llm_sticker / keyword_sticker）区分。
7. **合规**：站方内容 CC BY-NC-SA、禁止二次配布——插件只做随机引用转发（临时链直发），不落盘、不打包素材；README 署名致谢。
