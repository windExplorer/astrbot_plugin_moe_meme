# 萌萌表情包 — 设计说明

> PRD 全文在工作区 `docs/astrbot_plugin_moe_meme_PRD.md`（含 API 实测记录），本页只留架构要点与后续 TODO。

## 模块

- `main.py` — 全部 AstrBot 胶水：指令、llm_tool、消息监听、LLM 回复钩子、配置读写、会话状态。**不要加 `from __future__ import annotations`**（GreedyStr 哨兵按对象同一性识别，字符串化注解会让无参调用失效）。
- `wuwa_source.py` — 数据源。`StickerSource` 抽象暂未强行分层（只有 wuwa 一个源），加第二个源时再抽协议：`random_sticker(character?) -> Sticker` + `characters()` + `download()`。
- `sticker_gate.py` — 防打扰闸门，纯函数无依赖，`tests/test_gate.py` 可独立跑。
- `sticker_cache.py` — 本地表情缓存（落盘/找回/淘汰），纯 stdlib，`tests/test_cache.py` 可独立跑。

## 关键设计决定

1. **本地缓存后发送**：票券链约 16 分钟有效，三条发送路径（指令 / llm 工具 / 关键词 / 跟图）统一「先落盘再发本地文件」，下载失败回退直发票券链。缓存目录 `data/plugin_data/astrbot_plugin_moe_meme/cache`（StarTools，更新插件不清掉），`cache_max_files` 最旧淘汰。**仅本机器人运行时缓存**，不用于二次配布（站方 CC BY-NC-SA）。
2. **角色列表缓存**：archive-index 聚合，24h TTL；图片链本身不缓存 URL（失效快），只缓存文件。
3. **主动发送必须显式逐会话 opt-in**（`proactive_sessions`），刻意不随白名单「空=全放行」——空配置不能在所有群乱发。
4. **三类主动发送（LLM 工具 / 关键词 / 回复跟图）共享同一份会话闸门状态**：冷却与每日限额合并计数；`/表情包` 指令与主动共用同一份 `recent` 去重表。发送成功才记账。
5. **回复跟图的挂载策略**：`on_llm_response` 判定并预取 → `on_decorating_result` 并入回复链（非流式，文字+图一条消息）→ `after_message_sent` 兜底（流式下官方明确 decorating 可能不生效）。谁消费谁清 extra，保证不双发；与 llm 工具共享冷却，同一条回复不会两张。
6. **热重载**：`__init__` 按依赖序 reload `sticker_cache` / `sticker_gate` / `wuwa_source` 并重新绑定全局名（box/anima 同款做法）；新增顶层模块必须同步 `__init__` 重载列表与 `build_zip.ps1` 的 `$includeList`（后者有构建期守卫，漏了会打包失败而不是静默缺件）。
7. **配置的 `type: "dict"`**（aliases / triggers）是 AstrBot 的自由键值表类型，`check_config_integrity` 会保留用户自加的键；与固定子字段的 `type: "object"`（llm_sticker / keyword_sticker / reply_sticker）区分。
8. **合规**：站方内容 CC BY-NC-SA、禁止二次配布——插件只做随机引用 + 运行时缓存（不打包素材、不对外分发缓存文件）；README 署名致谢。
